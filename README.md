# Axon · Telegram-бот для записи

Первая рабочая версия демо: клиент записывается в Telegram, переносит или отменяет визит,
получает напоминания. Администратор управляет услугами, специалистами и рабочими интервалами
через Django Admin.

**Демонстрационный проект портфолио Axon.** Студия, услуги и специалисты вымышлены;
реальные услуги не оказываются. Не заявляем вымышленных клиентов или результатов.

## Что реализовано

- Услуга → специалист → дата → свободное время → подтверждение.
- «Мои записи», перенос и отмена с подтверждением.
- Повторное подтверждение не создаёт дубль.
- PostgreSQL запрещает пересечение действующих записей одного специалиста, включая
  одновременные запросы и услуги разной длительности. Соседние визиты разрешены.
- Перенос атомарно освобождает прежнее время, сохраняя стоимость и длительность визита.
- Рабочие интервалы по дням недели, обеденные перерывы и отсутствие специалиста.
- Напоминания за 24 часа и за 2 часа; устаревшие после отмены/переноса не отправляются.
- Уведомления администратору о создании, переносе и отмене, если задан его Telegram chat ID.
- При отмене через админку клиент получает отдельное уведомление.
- Адаптивная стартовая страница с каталогом и ссылкой на подключённого бота.
- Идемпотентное заполнение демокаталога: 3 услуги и 3 специалиста.

## Стек и архитектура

Python 3.13, Django 5.2 LTS, aiogram 3, PostgreSQL 17, Celery 5, Redis 7,
Gunicorn, WhiteNoise, Docker Compose. Проверки: pytest, pytest-django, Ruff.
Зависимости зафиксированы в `uv.lock`; сборка использует `uv sync --frozen`.

Один репозиторий и общая бизнес-логика, отдельные процессы для веб-приложения, бота,
worker и планировщика. Бот и админка используют общие сервисы и PostgreSQL;
отдельный HTTP API для MVP не требуется.

## Быстрый запуск

Нужен Docker с Compose v2. В корне проекта:

```bash
cp .env.example .env
docker compose up --build -d
docker compose exec web python manage.py seed_demo
docker compose exec web python manage.py createsuperuser
```

Если `.env` уже существует, сохраните свои настройки вместо повторного копирования.
Миграции применяются автоматически сервисом `migrate` до запуска приложения.
Повторный `seed_demo` не сбрасывает отредактированные данные.

- [Стартовая страница](http://localhost:8000/).
- [Админка](http://localhost:8000/admin/).
- [Проверка приложения и БД](http://localhost:8000/health/).
- Другой порт: `WEB_PORT=8001 docker compose up -d web`.

Для локальной проверки вместо `createsuperuser` можно выполнить:

```bash
docker compose exec web python manage.py create_demo_admin
```

Команда создаёт `demo_admin` со случайным паролем и показывает его один раз. Работает только
при `DJANGO_DEBUG=true`; существующий пароль не меняет. Если при первоначальной настройке
создан файл `.local-admin`, локальные данные входа находятся в нём. Этот файл и `.env`
исключены из Git.

## Подключение Telegram

1. Создайте отдельного демобота у [BotFather](https://t.me/BotFather).
2. Добавьте токен в локальный `.env`: `TELEGRAM_BOT_TOKEN=...`.
3. Укажите `TELEGRAM_BOT_USERNAME` без `@`, чтобы на странице появилась ссылка.
4. При необходимости укажите `TELEGRAM_ADMIN_CHAT_ID`. Администратор должен сначала
   начать диалог с ботом либо добавить его в нужную группу с правом отправки сообщений.
5. Пересоздайте процессы с новым окружением и включите бота:

```bash
docker compose --profile telegram up -d --force-recreate web bot worker beat
```

Откройте личный диалог в Telegram и отправьте `/start`.
Команды: `/book` — записаться, `/my` — мои записи, `/help` — справка.
Кнопки работают без временного состояния в памяти и переживают перезапуск процесса.

Используется long polling: нужен исходящий интернет, публичный webhook не требуется.
Запускайте **один** процесс бота на токен и **один** Celery Beat. Если демобот раньше
работал с webhook, сначала отключите его. Без токена веб-приложение и админка работают,
уведомления сохраняются в БД.

## Расписание и правила первой версии

- Одна компания; валюта демо EUR. Без предоплаты и внешних календарей.
- Часовой пояс студии: `STUDIO_TIME_ZONE=Europe/Berlin`. Он явно показан клиенту.
  Моменты времени хранятся с часовым поясом, длительности рассчитываются в UTC.
- Окно записи — ближайшие 14 календарных дней, шаг начала визита — 15 минут.
  Значения меняются через окружение.
- В демокаталоге: Пн–Сб, 09:00–13:00 и 14:00–18:00.
- В админке: «Специалисты» → рабочие интервалы; «Перерывы и отсутствие» → исключения.
  Изменение расписания влияет на новые записи и не отменяет существующие визиты.
  При добавлении отсутствия проверьте действующие записи и отмените конфликтующие отдельно.
- «Записи» — список с датами, фильтрами и действием «Отменить выбранные записи».
  Прямое изменение полей отключено, чтобы сохранять правила и напоминания.
  Создание и перенос в первой версии доступны клиенту через Telegram.
- Отмена и перенос разрешены до начала визита. Нет штрафов и минимального срока отмены.
  При переносе сохраняется специалист и услуга.
- Напоминание планируется, только если его срок ещё впереди при создании/переносе.
  Очередь проверяется каждые 30 секунд; временные ошибки повторяются до 5 попыток.

## Проверки

Тесты используют настоящий PostgreSQL, отдельную тестовую БД и подменённый Telegram API.
Сообщения реальным пользователям во время тестов не отправляются.

```bash
docker compose --profile test run --build --rm test
docker compose --profile test run --rm test ruff check .
docker compose --profile test run --rm test ruff format --check .
docker compose exec web python manage.py check
docker compose exec web python manage.py makemigrations --check --dry-run
```

Проверяются пересечения на уровне БД, гонка двух клиентов, соседние слоты, перерывы,
часовой пояс, идемпотентность, права клиента, атомарный перенос, отмена, устаревшие
напоминания, повторы доставки, админка и сценарий через реальную маршрутизацию aiogram.

## Разработка без контейнера приложения

Нужны Python 3.13+ и [uv](https://docs.astral.sh/uv/). PostgreSQL и Redis остаются в Docker:

```bash
cp .env.example .env
docker compose -f compose.yaml -f compose.dev.yaml up -d db redis
uv sync --frozen
```

В локальном `.env` задайте `DB_HOST=127.0.0.1`, `DB_PORT=54329`,
`REDIS_URL=redis://127.0.0.1:56379/0`. Для возврата к приложению в Docker
восстановите `DB_HOST=db`, `DB_PORT=5432`, `REDIS_URL=redis://redis:6379/0`.

```bash
uv run --env-file .env python manage.py migrate
uv run --env-file .env python manage.py seed_demo
uv run --env-file .env python manage.py createsuperuser
uv run --env-file .env python manage.py runserver
# Отдельные терминалы:
uv run --env-file .env python manage.py runbot
uv run --env-file .env celery -A config worker --loglevel=INFO
uv run --env-file .env celery -A config beat --loglevel=INFO --schedule=/tmp/axon-celerybeat
uv run --env-file .env pytest
uv run ruff check .
```

## Эксплуатация и ограничения

`docker compose logs -f web worker beat` — логи; добавьте `bot` после его подключения.
`docker compose down` останавливает проект с сохранением томов данных.
PostgreSQL и Redis по умолчанию не открыты на хосте, веб-приложение слушает только localhost.

`.env.example` предназначен для локального демо. Перед публикацией задайте случайный
`DJANGO_SECRET_KEY` длиной не менее 50 символов, `DJANGO_DEBUG=false`, свои пароли БД,
разрешённые домены и CSRF origins. Настройте HTTPS и резервные копии. Приложение требует
HTTPS в production по умолчанию; доверие к заголовкам прокси настраивается под конкретный
reverse proxy. Не публикуйте токен и локальные пароли в репозитории.

Блокировка записи и проверка её ревизии защищают от обычных дублей уведомлений и отправки
устаревшего напоминания после завершённой отмены. Если процесс аварийно завершится между
успешной отправкой в Telegram и фиксацией транзакции, при повторе возможен дубль:
Bot API не предоставляет ключ идемпотентности для отправки сообщений.

Живая отправка Telegram требует собственного токена и отдельной ручной проверки.
Дальнейшие улучшения: календарь администратора, создание/перенос из админки,
политика хранения персональных данных, скриншоты диалога, видео и кейс для сайта Axon.
